# Music transition transport fixture

Local generated eight-second PCM WAV tones, two fictional Jellyfin 10.11.11 accounts with disjoint tracks/tokens, bounded request/report observations. Reuses the app's version-checked original stream and media-type contract. No real server or library data. Requests for another account's audio are rejected; unmodeled operations return 501. Source-derived local fixture; owner mock discovery was skipped because the installed CLI does not provide postman status.

Expected acceptance: native playlist handoffs occur in exact queue order; Playing follows file-loaded, and metadata/progress identifies the actual current source. Crossfade starts only after the prepared music decoder is ready, uses complementary gains and never overlaps books/podcasts/radio or sleep-timer sessions. Queue edits, seek, pause, Stop, output/settings changes and failed next streams cancel or safely recover preparation. Different account/header contexts must never reuse a credential-bearing MPV prefetch. No stale prepared result may replace a later queue choice. Observe both MCTransition log events and source-scoped HTTP/Playing/Stopped reports; a command accepted without FILE_LOADED is not success.

Controls: failStream and failResolve accept a fictional track GUID; delay adds up to three seconds of stream delay. reset clears only fixture observations. Stop the simulation and remove both generated emulator connections after acceptance. This fixture does not establish audible DAC continuity or output mixing behavior on Samsung; those require final hardware tests.
